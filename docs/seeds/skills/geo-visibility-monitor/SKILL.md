# geo-visibility-monitor

> GEO clients pay for one number moving up: how often AI engines name
> them when a real buyer asks. This skill turns recorded prompt runs
> into that number, the monthly report, and the delta since last time.
> It measures — it never fabricates and it never queries engines itself.

## Inputs
- `customer_slug` — the client to score. If omitted, scores every
  customer with recorded GEO runs.
- `~/Documents/businesses/_shared/customers/{slug}/07-geo/prompt-runs.jsonl`
  — the recorded runs (see data contract). Runs are recorded by Jack or
  imported from the tracking tool (Otterly or equivalent), never
  generated by agent code.

## Data contract — prompt-runs.jsonl

One JSON object per line, append-only:

```json
{
  "timestamp": "2026-07-09T14:00:00Z",
  "engine": "chatgpt" | "perplexity" | "google-ai",
  "prompt": "best pool service in naples fl",
  "mentioned": true,
  "position": 2,
  "sentiment": "positive" | "neutral" | "negative",
  "citation": "https://..."
}
```

`position` is the client's rank among named businesses in the answer
(1 = named first); null/absent when unranked or not mentioned.

## Scoring rubric (/20)

For each distinct (prompt, engine) cell, the LATEST run wins:
- 0 pts — not mentioned
- 1 pt — mentioned
- 2 pts — mentioned in the top 3 named businesses

`score = round(20 × points / (2 × cells))`. No runs → score is null
(never zero — "unmeasured" and "invisible" are different states).

## Output
1. Report at `customers/{slug}/07-geo/report-YYYY-MM-DD.md` — score,
   delta, per-engine breakdown, weakest cells ranked for next month's
   content work.
2. Appended line in `customers/{slug}/07-geo/score-history.jsonl`
   (append-only — the trend IS the deliverable).
3. Audit-log entry (`geo_visibility_report_generated`).

## Hard rules

1. **Never query AI engines from agent code.** No API calls with real
   keys (CLAUDE.md rule 3). Runs come from Jack or a tracker export.
2. **Never fabricate or extrapolate mention data.** Missing cells stay
   missing; the score normalizes over measured cells only.
3. **Never overwrite score history.** Append-only, like every dossier
   artifact.
4. **Prices only from `src/lib/pricing.ts` (GEO_TIERS).** Reports that
   mention the service price import it — never hard-code.
5. **A score drop ≥3 points surfaces in next_actions for Jack.** No
   automated client communication about drops — ever.

## Failure modes

- **No prompt-runs.jsonl / empty file** → score null, report skipped,
  next_action: "record a baseline with the GEO prompt pack".
- **Single engine measured** → score computes but the report flags
  partial coverage; do not compare against a 3-engine baseline.
- **Malformed lines** → skip them, count skips in the report; never
  crash the monthly run over one bad line.
- **Client churned mid-month** → still produce the final report; it is
  part of the case-study record.

## When invoked
- Monthly per GEO client (Essentials/Growth cadence), after new runs land
- After the initial $750 audit's baseline runs are recorded
- Manually when Jack asks "what's {client}'s visibility score"

## Logging
`[YYYY-MM-DD HH:MM ET] geo-visibility-monitor → customer: {slug}, cells: N, score: S/20, delta: ±D`
