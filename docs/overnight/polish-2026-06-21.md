## What I changed (committed)

**Build-safety: guarded the `matchingSkus` lookup against a renamed `SkuId`.**
Line 33 was:

```ts
const matchingSkus = SKUS.filter((s) => v.recommendedSkus.includes(s.id));
```

If a SKU id is ever renamed in `site.ts` (e.g. `"portal"` → `"portal-v2"`) so
that a vertical's `recommendedSkus` no longer resolves, this silently returns
`[]`. The "Recommended SKUs" section then renders an **orphan sentence** —
"the natural fit is **.** Pricing fixed" (bare period, double space) — and an
**empty pricing grid** under a "Recommended SKUs" header. This is the same
rename-time failure mode `/about` had with `.find(...)!.setupLabel`, just
softer (broken copy instead of a build throw). Replaced with a guarded
fallback that degrades to the full SKU list:

```ts
const recommendedSkus = SKUS.filter((s) => v.recommendedSkus.includes(s.id));
const matchingSkus = recommendedSkus.length > 0 ? recommendedSkus : SKUS;
```

Behavior is **byte-identical today** — all three verticals resolve ≥2 SKUs, so
nothing renders differently. It only changes the failure mode: a broken
pricing section becomes a still-selling one.
