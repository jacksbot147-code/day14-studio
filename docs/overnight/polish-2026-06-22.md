## What I changed (committed)

**Build-safety: hardened the three `new URL(...).host` call sites against a
malformed or scheme-less URL in hand-entered build data.**

The page read build URLs straight into `new URL()` twice:

```tsx
// Header CTA
Open {new URL(build.productionUrl).host} ↗
// NowShowing embed chrome + fallback link
const host = new URL(url).host;
```

`new URL()` **throws** on an invalid URL. `BUILDS` in `src/lib/builds.ts` is
hand-entered, so the single most likely data-entry mistake — a `productionUrl`
or `previewUrl` written without a scheme, e.g. `"splashjackspools.com"` instead
of `"https://splashjackspools.com"` — would throw at render time. Because this
is a statically-generated route, that throw doesn't just blank one section: it
**fails `generateStaticParams` for that build and breaks the build**. This is
the same data-entry → page-break failure class the verticals and about passes
flagged, just one that crashes hard rather than rendering broken copy.

Fix: a small local `hostOf()` helper that tries `new URL(url).host` and, on
failure, falls back to the raw string with any scheme stripped:

```tsx
function hostOf(url: string): string {
  try {
    return new URL(url).host;
  } catch {
    return url.replace(/^[a-z]+:\/\//i, "");
  }
}
```

Behavior is **byte-identical today** — every URL in `BUILDS` is a valid
absolute `https://` one, so `hostOf` returns exactly what `new URL().host`
returned. It only changes the failure mode: a future data typo degrades to a
slightly-off host label instead of taking down the route's build.
