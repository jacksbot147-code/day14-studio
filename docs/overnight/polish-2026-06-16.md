## Gaps found vs SKILL.md spec + CLAUDE.md hard rules

1. **Spec failure mode "New customer (<7d) → insufficient data → baseline 20"
   was unimplemented.** A brand-new customer with no work-register history scored
   0 (green) — indistinguishable from a proven-healthy customer. Fixed: read
   `signup_date` from the dossier `01-brand.json` (new `readSignupDate()`,
   best-effort/error-safe) and assign baseline 20 *only when there are no real
   risk signals yet* — a genuine cancel/payment-fail in the first week is real
   and still survives (verified by test).

2. **Spec failure mode "Score 100 from single signal → cap at 80 unless 3+
   signals present" was unimplemented.** Fixed: `if (signals.length < 3) score =
   min(score, 80)`. A customer with fewer than three signals can no longer land
   in the red bucket (which triggers a "personal call from Jack within 24h"
   recommendation). Defensive against one noisy signal driving a red alert.

3. **CLAUDE.md hard rule 5 ("always audit-log consequential actions") unmet.**
   The report gates Jack-tap personal outreach but left no audit entry. Fixed:
   `churn_risk_report_generated` entry via `auditLog()` with report path,
   customers scored, red/orange counts, and total LTV-at-risk in details.
   Mirrors the customer-ltv-calculator pattern.

4. **`run()` computed `computeChurnRisks()` twice** (once inside
   `writeChurnReport()`, once directly) — wasteful and racy across a month
   boundary. Fixed: compute once, pass precomputed risks into
   `writeChurnReport(precomputed?)`. Same fix shape as the ltv polish.

5. **No error handling in `run()`** — any fs throw escaped raw to the dispatch
   layer. Fixed: try/catch → `{ ok: false, error }` outcome.

6. **Spec input `customer_slug` (single-customer mode for `/risk {slug}`,
   dispatch.ts:89) was ignored.** Fixed: when `ctx.customer_slug` is set the
   outcome `result` now carries `customer` + `customer_found`, matching the ltv
   skill's `/ltv {slug}` shape. Full-book report still written either way.

7. **Hard rule 4 ("never email red customers en masse") made explicit in the
   outcome.** `next_actions` now reads "Personal 1:1 outreach … — no mass email"
   and `jack_tap_required` fires on any red, routing to a human rather than any
   automated send.

**Growth hook:** `logSkillInvocation` is fired centrally in
`skill-runtime.ts` (`runSkill`, ~line 132), so it is intentionally NOT re-called
in-skill — verified, not added (same call made on the uptime-monitor and
refund-handler nights; avoids double-logging).
